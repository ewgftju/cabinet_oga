# SAQ · Кабинет ОГА

Кабинет представителя объекта. На первом экране показан реестр проверок с разбивкой по годам. Внутри мероприятия хранятся отдельно полученные PDF, их редакции, отметки об ознакомлении и ответы на пункты предписания профконтроля.

## Демонстрация

Требуется Node.js 22.13 или новее. У приложения нет внешних npm-зависимостей.

```sh
npm run dev
```

Адрес демо по умолчанию — http://localhost:4173. В верхней панели «Демообъект» переключает вымышленные профили. Для первого объекта доступны одноимённые проверки разных лет и две редакции требования. В профиле «ТОО „Аудит Сараптама“» есть предписание с двумя пунктами для отправки ответов. Данные о действиях хранятся в IndexedDB этого браузера. Смена профиля сохраняет отметки текущего объекта.

`npm run build` собирает автономный демонстрационный стенд в `dist/`. Vercel публикует только этот каталог. В публичных материалах используются условные идентификаторы, вымышленные организации и образцы документов. Демо-PDF поставляются в сжатом архиве. Пересборка при изменении сценариев — `python3 scripts/make_demo_pdfs.py` (ReportLab, Liberation Serif). Источником текста ст. 155 для демоформы послужил экземпляр справочного приложения в профконтроле SAQ. Рабочий сервис всегда выдаёт PDF, полученный от модуля-отправителя.

## Доступные направления и документы

| Профиль | Направления |
| --- | --- |
| Государственный и квазигосударственный сектор | ВГА, СВА |
| Частный сектор с категорией из справочника | Профилактический контроль |

Категории профконтроля — аудиторская организация (АО), профессиональная аудиторская организация (ПАО), ОПИ, ПОБ, ОПСБ, палата оценщиков (ПО) и оценщик (ОЦ, отдельный демонстрационный профиль). Сектор и категорию берут из карточки с БИН или ИИН. Организационно-правовая форма в названии объекта не определяет доступ.

* ВГА и СВА направляют поручение, дополнительное поручение, аудиторский отчёт, аудиторское заключение, предписание и требование.
* Профконтроль направляет уведомление, акт о назначении, проверочный лист, памятку по ст. 155, акт о результатах и предписание. Дополнительный акт, протокол об отказе и результаты рассмотрения возражения появляются при отдельной отправке объекту. Служебные материалы и документы для ЕРСОП исключены из входящих.
* Открытие или скачивание PDF не создаёт отметку. Кнопка «Подтвердить ознакомление» фиксирует представителя и время для данной отправленной версии.

## Сервис для подключения SAQ

`npm start` запускает HTTP-сервис и читает файлы интерфейса из `web/`. Печатные формы, отметки и вложения хранятся в SQLite. Сервис размещают на постоянном томе за HTTPS-шлюзом авторизации SAQ. Модель работает с подписанным токеном, в том числе в HttpOnly cookie `saq_access`, которую выдаёт шлюз. Для тестового рабочего контура также поддерживается заголовок `Authorization: Bearer <JWT>`. Обязательны RS256, серверный публичный ключ, точное совпадение issuer и audience, действующий срок токена и связь его `sub` с объектом.

| Переменная | Назначение |
| --- | --- |
| `OGA_ISSUER`, `OGA_AUDIENCE` | Ожидаемые issuer и audience токена SAQ |
| `OGA_PUBLIC_KEY` | Путь к PEM с публичным ключом IdP |
| `OGA_DIRECTORY` | Путь к JSON-справочнику объектов и представителей |
| `OGA_DB` | Путь к постоянной БД, по умолчанию `var/cabinet.sqlite` |
| `OGA_SOURCE_VGA`, `OGA_SOURCE_SVA`, `OGA_SOURCE_PROF` | Отдельный серверный ключ каждого подключённого модуля, минимум 32 символа |
| `HOST`, `PORT` | Адрес и порт, по умолчанию `127.0.0.1:4173` |

Минимальная структура справочника:

```json
{
  "objects": [
    {"id":"000000000101", "idType":"bin", "sector":"state", "name":"Пример учреждения", "region":"г. Астана"},
    {"id":"000000000103", "idType":"bin", "sector":"private", "category":"АО", "name":"Пример аудиторской организации"}
  ],
  "representatives":{"example-sso-sub":"000000000101"}
}
```

Поддерживаются `state`, `quasi`, `private` и идентификаторы `bin` / `iin`. Шлюз выставляет cookie для кабинета с флагами HttpOnly, Secure и подходящим SameSite. Доверенная привязка представителя определяется по справочнику. URL, название организации и поля клиентской формы не могут менять текущего получателя. При изменении справочника или ротации ключа сервис перезапускают с обновлёнными файлами.

### Отправка из модуля-источника

`POST /api/sources/{vga|sva|prof}/deliveries` принимает JSON с `Authorization: Bearer <ключ этого источника>`. Пример структуры (поле PDF заполняется полным содержимым файла):

```json
{
  "recipient":"000000000101", "audience":"subject", "status":"sent",
  "case":{
    "id":"unique-case-2026", "revision":1, "number":"ВГА-2026-042",
    "title":"Аудит использования бюджетных средств", "issuer":"Департамент внутреннего государственного аудита",
    "start":"2026-10-26", "end":"2026-11-20", "status":"active"
  },
  "document":{
    "id":"outgoing-order-17", "kind":"instruction", "version":1, "number":"42/01",
    "sentAt":"2026-10-26T05:30:00Z", "pdfBase64":"<PDF в base64>"
  }
}
```

Для каждого нового мероприятия источник выдаёт стабильный идентификатор. Ключ дела состоит из источника, идентификатора дела и получателя. Несколько объектов одного аудита могут получить разные экземпляры. Для отправленной редакции уникальна комбинация дела, исходного ID документа и версии. Повторная доставка идентичного PDF идемпотентна. Изменённый документ с прежней версией возвращает HTTP 409. Новые версии и повторные проверки сохраняют предыдущие файлы и отметки.

Коды ВГА и СВА — `instruction`, `additional`, `report`, `conclusion`, `prescription`, `request`. СВА также принимает свои коды `assignment` (поручение) и `requirement` (требование). Для ВГА `assignment` обозначает внутреннее аудиторское задание и не публикуется. Для профконтроля доступны коды из `profKinds` в `web/catalog.js`. Поле `document.points` у предписания профконтроля принимает массив объектов с полями `id`, `text`, `deadline` (YYYY-MM-DD). Максимальный размер исходного PDF — 20 МБ.

`PATCH /api/sources/{source}/cases` с полями `recipient` и `case` обновляет реквизиты уже полученного дела, в том числе статус `active`, `execution` или `closed`. Для изменения нужна увеличенная `case.revision`. Повтор события старой редакции не откатывает статус. Историческая проверка сохраняет получателя, направление и категорию, с которыми она поступила.

### Получение отметок и ответов источником

`GET /api/sources/{source}/events?after=0` возвращает до 100 событий этого источника в порядке `seq`. Сохраните последний обработанный `seq` как курсор. Событие `acknowledged` содержит представителя и время. Событие `execution-response` содержит пункт предписания, меры, дату исполнения, автора и идентификатор вложения. В обоих случаях передаются исходные ID дела, документа, получатель и версия. Вложение доступно по `GET /api/sources/{source}/attachments/{id}` с тем же ключом. Повтор запроса с прежним курсором позволяет восстановить доставку. В демонстрации обмен с боевыми модулями отключён.

## Проверка

```sh
npm test
npm run build
```

Тесты проходят через HTTP и постоянную БД. Они проверяют повторные проверки и редакции, выдачу исходных байтов PDF, повторы и параллельные подтверждения, изоляцию получателей, соответствие видов документов направлениям, ответы по пунктам и чтение событий модулем-отправителем.
